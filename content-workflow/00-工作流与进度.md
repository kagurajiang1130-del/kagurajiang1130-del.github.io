# 商业网站多 Agent 访谈与成稿工作链

## 目标

这套工作链由总编排、同类官网研究、文案策略、访谈、含义提炼、服务产品化、网站文案、独立审稿和确认归档角色协同，把创始人朴素、抽象、甚至暂时说不完整的想法，放进经过市场研究的专业内容框架中，逐步发展成三类可以长期使用的成果：

1. 真实、清晰的品牌与商业判断；
2. 客户看得懂、愿意继续咨询的网站文案；
3. 可以安全写入 `app/content.ts` 的日语、英语、简体中文内容。

这不是一次性问卷，也不是一个 Skill 独自完成全部工作。每次只处理一个 Part；专业角色默认只读，先把完整结果展示给用户，用户明确确认后才写入文件。

## 每个 Part 的固定循环

1. **只读发现**：先检查目录、旧 Chat、现有 MD、已确认内容和当前 Part，不重复劳动，也不修改文件。
2. **同类官网研究**：研究 Agent 查阅当前仍可访问的相似公司官方页面，分析这一 Part 常见的结构、客户问题、证明方式、CTA、行业套话与不同写法；所有观察保留直接链接。
3. **文案策略**：策略 Agent 不照抄同行，而是确定这一 Part 对客户承担什么任务、推荐的信息顺序、需要创始人决定什么，以及最终文案 Agent 的任务书。
4. **立场访谈**：访谈 Agent 根据策略中的决策点提出 3–5 个问题，询问本公司的理念、选择、理由、边界和必要事实。创始人可以用抽象、哲学或暂时不完整的方式回答；默认不追问趣事，也不要求用户写标题、商业术语或成段文案。
5. **思想发展与事实分层**：提炼 Agent 区分用户原意、公司事实、外部研究、编辑推导和未知项，并把重要抽象思想依次转换为“哲学原则 → 客户处境 → 公司判断 → 实际工作影响 → 责任边界 → 客户能听懂的表达”。允许从已确认理念发展客户意义，但不能发展出虚假的能力、案例或结果。
6. **条件式商业处理**：服务、流程和价格 Part 再调用服务产品化 Agent，明确可售范围、交付物、输入、非目标和价格逻辑。
7. **原创网站成稿**：`copywriting` 根据策略任务、用户立场、已确认事实和必要商业结构，写成完整的客户可读版本，而不是把访谈答案换一种说法。
8. **独立审稿**：新子 Agent 检查研究使用、原创性、信息结构、思想发展质量、忠实度、商业用途、跨 Part 一致性和无依据主张；`BLOCK` 时不得进入保存。
9. **先展示**：总编排在对话中展示研究如何影响结构、用户立场与编辑发展、完整网站成稿、未知项、审稿结论和计划写入位置。此时仍然零写入。
10. **明确确认**：只有用户明确指向当前版本说“确认 / 保存这一版”才算批准；“不错、继续、你看着办”只算反馈。
11. **确认后归档**：归档 Agent 才把原话、研究索引、提炼和成稿写入约定 MD，并检查目标范围 diff。
12. **全部完成后集成**：先完成中文母稿，再分别进行日语与英语的文化适配；经单独确认后更新 `app/content.ts`、测试并按需重新发布。

- `研究中`：正在查阅相似公司官网并形成有来源的研究包；

- `访谈中`：正在准备问题或收集用户原话，尚未写入；
- `提炼中`：专业角色正在生成与审查候选内容，尚未写入；
- `待确认`：已经在对话中展示成稿，等待用户校正或明确批准；
- `已确认待保存`：当前展示版本已经获得明确批准；

- `已发布`：已经测试并发布到公开网站。

## 成品质量标准

- 保留思想的独特性，不把它压扁成“专业、创新、赋能”之类空话；
- 同行研究用于发现客户问题与内容结构，不复制同行的口号、独特隐喻、句式或整套叙事顺序；
- 用户只需提供公司的思想、选择、边界和真实事实，文案 Agent 负责把它发展成完整内容，而不是复述回答；
- 抽象不是问题；最终成稿仍必须具体说明客户遇到什么、公司如何判断、工作会发生什么变化以及哪些结果不能承诺；
- 每一段都能回答客户的“这和我有什么关系”；
- 把功能连接到具体结果，但没有证据时不承诺数字或效果；
- 把内部分析转化成客户能买到、拿到、使用的东西；
- 每项服务都说明工作、交付物、客户要提供什么以及明确不包含什么；
- 页面有一个清晰的主要行动，不让客户在多个模糊按钮之间犹豫；
- 中文先确认思想，日语和英语做语境适配，不机械直译。
