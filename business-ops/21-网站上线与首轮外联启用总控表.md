## B. 访客可见字段门

正式新版不得继续公开以下原始占位符：

- `[BRAND NAME]`、`[CONTACT EMAIL]`；
- “后续补充／will be added later／後ほど追加”类正文；
- 虚拟团队、Logo、图片、客户、行业、成果和案例字段；
- 指向 `#contact` 的伪 SNS 链接；
- 无真实目标的 Privacy Policy。

如果还没有客户案例，应改成三语诚实空状态，例如“目前没有获得公开授权的案例”，而不是展示 `Case Study 01–03` 占位项目。

## C. 自动发布门

运行：

```text
npm run audit:publication
```

当前审计应报告 `readyToPublish: false`，并列出 8 个阻断项：

1. 没有精确发布批准记录；
2. Part 01–10 尚未全部批准；
3. 品牌名称仍是占位符；
4. 对外邮箱仍是占位符；
5. 访客可见内容仍有原始占位符；
6. SNS 链接未填写或移除；
7. Privacy Policy 没有真实目标；
8. 正式 SEO 索引尚未启用。

`.github/workflows/github-pages.yml` 在真正部署前执行：

```text
npm run audit:publication:strict
```

任何阻断项存在时，部署任务失败，旧公开站不会被新版替换。只有用户明确回复精确口令 `确认公开发布新版` 后，Codex 才能填写 `release/publication.json` 的批准状态；不能由 Agent、测试脚本或提交信息自动代替用户授权。
